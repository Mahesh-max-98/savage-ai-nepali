# Savage AI Nepali — setup

This repository contains a Flask dashboard and a separate background worker. The worker generates an original Nepali/Nepanglish caption, creates an image, checks recent captions for near-duplicates, and publishes a photo post to a Facebook Page when automation is enabled.

## Current architecture

- Flask + Gunicorn dashboard
- PostgreSQL for settings, history, and generated image bytes
- Groq chat completions for captions
- OpenAI Images API for image generation
- Meta Graph API Page Photos endpoint for publishing
- Separate Render background worker for scheduled publishing

## Required private environment variables

Set these in the Render Dashboard. Never put their values in GitHub, source code, screenshots, or chat messages.

| Variable | Purpose |
|---|---|
| `SECRET_KEY` | Flask session signing key (generated by the Blueprint) |
| `DASHBOARD_PASSWORD` | Password used to sign in to the dashboard |
| `GROQ_API_KEY` | Caption generation |
| `OPENAI_API_KEY` | Image generation |
| `FACEBOOK_PAGE_ID` | The Page ID to publish to |
| `FACEBOOK_PAGE_ACCESS_TOKEN` | Page access token with the required publishing access |

The Blueprint also sets `DATABASE_URL`, `GROQ_MODEL`, `IMAGE_MODEL`, and `META_GRAPH_API_VERSION`.

## Facebook Page permissions

The Meta app and the person authorizing it must have the appropriate Page task and permissions. The current Page Photos documentation lists the Page's `CREATE_CONTENT` task and the `pages_read_engagement`, `pages_manage_posts`, and `pages_show_list` permissions. Review the official Meta documentation and the permissions granted to your own Page before enabling automatic publishing.

Official reference: https://developers.facebook.com/docs/graph-api/reference/page/photos/

## Deploy on Render

1. Open the Render Blueprint setup page for this GitHub repository.
2. Review the proposed resources and their current prices before applying.
3. Set `DASHBOARD_PASSWORD`, `GROQ_API_KEY`, `OPENAI_API_KEY`, `FACEBOOK_PAGE_ID`, and `FACEBOOK_PAGE_ACCESS_TOKEN` in the private environment-variable form.
4. Apply the Blueprint only after reviewing the costs.
5. Open the dashboard URL, sign in, check the service connections, and press **Start automation**.

The Blueprint uses a paid always-on web service, a paid background worker, and a paid PostgreSQL database. Do not apply it until you have reviewed the current Render pricing and have permission to use the selected billing account. API providers may also charge for text and image generation.

## Local development

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export SECRET_KEY="replace-this-for-local-testing"
export DASHBOARD_PASSWORD="choose-a-local-password"
flask --app app run
```

In a second terminal, run the worker:

```bash
python worker.py
```

A local `.env` file may be used with your own environment loader, but it is ignored by Git. Do not commit it.

## Important operating notes

- Automation is paused by default. You must start it from the dashboard.
- The default schedule is 30 minutes, with a maximum of 48 posts per day. High-volume posting may be treated as spam; keep posts original, varied, and relevant, and reduce the frequency if Page quality drops.
- Every scheduled post requires both a caption provider and image provider. If image generation fails, the post is not published.
- The app does not store provider API keys in PostgreSQL.
- The image bytes are stored in PostgreSQL so dashboard previews do not depend on the worker's local filesystem.
- A generated post can also be created manually from the dashboard and published manually.
- Review generated content and Page activity regularly. Automated publishing should not be used for harassment, hateful content, deceptive claims, or impersonation.
